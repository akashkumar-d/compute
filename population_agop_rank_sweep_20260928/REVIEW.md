The material scientific checks pass:

1. **Raw normalization:** gamma=[r Var(q)+r² E(q)²]^(-1/2) gives E[Y²]=1 and Var(Y)=Var(q)/(Var(q)+r E(q)²). It agrees with both existing engines. Profiling the intercept preserves the raw teacher; reporting normalized loss does not normalize training gradients. The h2 variance stays one; raw-ReLU variance decreases from 0.517094 at rank2 to 0.118049 at rank16. The ReLU runner correctly receives raw stops 0.01 Var(Y), while SwiGLU receives normalized stop0.01. Every rank8 control is rerun under the new common settings.
2. **Teacher signal:** using beta=E[Zq(Z)] and eta=E[q'(Z)²], aggregate/transverse teacher-AGOP eigenvalues are gamma²[eta+(r−1)beta²] and gamma²[eta−beta²]. The stored numbers agree. h2 has weakest eigenvalue2/r; raw ReLU has gamma²/4 and aggregate/weakest ratio r+1. These are target properties, not evidence of a learned student subspace.
3. **Baseline and width:** r/d is an expectation for mean alignment or random top-direction capture, not for A_min. The criterion correctly subtracts each arm's measured initial A_min and retains the ≥0.5 gain threshold. No subspace intersection is forced at these ranks in d64. Fixed widths256/64 imply decreasing width per teacher direction; the protocol does not claim an isolated infinite-width rank law. The inherited ReLU l1 cap64sqrt(r) varies with rank, so its cross-rank refit comparator is not a fixed-budget class; this is explicitly disclosed.
4. **Pairing and scope:** the initialization source uses fresh generators keyed only by seed and fixed shape/scale, so within-student Gaussian arrays are intended to match across rank and teacher. Source inspection supports the design, while recorded array hashes remain required before claiming an executed match. Seeds641/642 are reused development seeds; no independent confirmation or cross-architecture array equivalence is claimed.
5. **Numerical comparability:** every SwiGLU cell uses the same provisional `(32,96,48,24)` recipe and head rate0.01. The requested comparison to `(64,192,96,48)` includes the actual block-weighted update and adaptive step, not only the unweighted gradient. Rank16 is structurally accepted by the existing validator, but none of these static checks certifies its numerical accuracy, representability, or eventual learning. The first two ReLU teacher links use the existing analytic cross moments and angular student kernel; this does not eliminate conditioning or stable-AGOP concerns.
6. **Outcome qualification:** initial all-update 1%/5% windows, same-checkpoint minimum-alignment/refit conditions, and later raw loss release in units of variance remain unchanged. The protocol correctly requires the canonical summary rule: the native ReLU runner's inherited raw-refit `>1e-5` flag is not the required `0.1 Var(Y)` event. Numerical sensitivity, rank/gap flags, and all pending/capped/unresolved outcomes remain explicit.

The remaining limitations are already disclosed and should remain in result interpretation. Increasing rank changes raw signal amplitude for nonzero-mean links, width per direction, baseline weakest-angle geometry, and the ReLU refit budget. A common nominal clock therefore does not promise equal learning opportunity or accuracy. Descending-rank scheduling may shorten observation for the final rank2 cells because 3600 seconds is less than two complete 1990-second allocations. Compare common attained support, report actual censoring, and do not convert a cap into evidence of failure.

No further scientific changes are required to this reviewed design. A promising finite-order result still needs the planned state/update checks and trajectory validation where sensitivity appears. This PASS does not establish a successful rank trend, an all-direction plateau, or permission to omit unsuccessful ranks, pool unmatched historical controls, or expand the full 224-arm grid without the stated staged review.
